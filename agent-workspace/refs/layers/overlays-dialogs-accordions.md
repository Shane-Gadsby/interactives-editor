# Accordions, tabs, overlays (tooltips, modals, confirms, prompts) and dialogs

A frame or group can be an accordion: disclosure {open: one|many, variable (a number variable for one, counting from 0 with -1 for none; a list variable for many), toggle? (one only: clicking the open section closes it), panels? (a container inside it whose children are the panels, matched to the frame's other children in order, which makes it a set of tabs)}. Each child is a section: its first layer is the header and the rest is the panel, unless panels says otherwise. The clicking, the showing and the aria-expanded on each header are the frame's own job, so an accordion needs no interaction nodes. overlay {overlayId, trigger?, side?, offset?, inputs? (values handed to the overlay as it opens from this layer, by variable name, so one overlay can ask a different question from each layer; the page lists what it takes in props), inputExprs? (the same by variable name as expressions worked out as it opens, winning over inputs: layer.name, and in a repeater copy item and index, so one link on a template serves every copy)}; the overlay page's own graph can have event.overlayOpen and event.overlayClose (event.layer, event.index, event.inputs) on a layer shows an overlay page for it: that layer is the target (a tooltip sits beside it), and the trigger is the same layer unless another id is given. The page is an artboard with overlay {kind: tooltip|modal|confirm|input (confirm asks with buttons, input asks for something typed and is what the editor calls a prompt; an old file's prompt is read as confirm), side?, offset?, scrim?, openVariable?, and for a tooltip fade? (ms to fade in and out; absent uses settings.hugDuration, 300 by default), tail? (a triangle pointing at the target, on unless false), stay? (stays open while the pointer is on the tooltip itself so links inside can be reached, on unless false)} on it. When the overlay page holds a single frame, that frame is the card: the overlay is drawn at the card's own auto-layout size (a tooltip as wide as its words), and the page is only where it is designed, set with set_artboard; an overlay page is never opened on its own, never counts in pageCount and never grows a fitted page. A modal, confirm or input shows while its openVariable is on, and a click on the trigger turns it on, so a Close button inside is a plain Set variable. A frame can be a dialog: dialog {modal (default true), scrim (a solid paint over the artboard behind it, drawn as its own full-page backdrop right under the dialog, so see-through parts of the dialog show the dimmed page), closeOnEscape (default true), closeOnOutsideClick, initialFocus (layer id), returnFocus (default true), openVariable (variable id: the frame shows while it is on, Escape turns it off)}. A dialog opens over the page: it never counts towards a fitted page height, and nor does any layer with hugIgnore true (toasts, tooltips, anything floating).
